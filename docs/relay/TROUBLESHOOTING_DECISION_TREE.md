# Relay Network Pairing Troubleshooting Decision Tree

When pairing your mobile device or secondary screen with your development machine via QR code or short code, connection failures almost always stem from local network topology or OS firewalls. Follow this decision tree to pinpoint and resolve the issue.

## 1. Network & Subnet Checks

### Symptoms
- Safari/Chrome on phone shows `Could not connect to server` or `ERR_CONNECTION_TIMED_OUT`.

### Checks
1. **Identical Wi-Fi SSID**: Verify both your laptop and phone are connected to the exact same Wi-Fi network. If your router splits 2.4GHz and 5GHz into separate SSIDs (`Home-2.4G` and `Home-5G`), ensure client isolation between bands is turned off or join the same band.
2. **Access Point (AP) Client Isolation**: Many public Wi-Fi networks (cafés, hotel Wi-Fi, university dorms) enable "Client Isolation", which prevents wireless devices from talking to each other.
   - *Fix*: Connect both devices to a personal mobile hotspot, or use Relay Pro Remote Mode.
3. **Subnet Match**: Inspect IP addresses.
   - Laptop: `192.168.1.45`
   - Phone: `192.168.1.88`
   - If one is `192.168.1.x` and the other is `10.0.0.x`, they are on isolated networks (e.g. guest network).

## 2. Operating System Firewall

The Relay LAN gateway listens on port `7331` by default.

### macOS
1. Open **System Settings > Network > Firewall**.
2. If Firewall is ON, click **Options...**.
3. Ensure "Block all incoming connections" is unchecked.
4. Allow incoming connections for `bun` or the Relay binary.

### Linux (ufw / iptables)
```bash
# Allow inbound port 7331 on local subnet
sudo ufw allow 7331/tcp comment "Relay Local Gateway"
```

### Windows Firewall
```powershell
# Run PowerShell as Administrator:
New-NetFirewallRule -DisplayName "Relay Local Gateway" -Direction Inbound -LocalPort 7331 -Protocol TCP -Action Allow
```

## 3. VPNs & WSL2 Environments

### Active VPN on Host
Corporate VPNs (e.g. Cisco AnyConnect, GlobalProtect, Tailscale with exit nodes) often route all traffic through virtual adapters and block direct LAN communication.
- *Fix*: Enable "Allow local LAN access" in your VPN client settings, or temporarily disconnect the VPN while testing on local Wi-Fi.

### Running Inside WSL2 (Windows)
WSL2 runs inside a lightweight Hyper-V virtual machine on a separate internal subnet (`172.x.x.x`). Phones on your physical Wi-Fi router cannot reach `172.x.x.x` directly.
- *Fix*: The Relay CLI automatically detects WSL2 and recommends the physical Windows adapter IP. Relay also supports port-forwarding:
  ```powershell
  netsh interface portproxy add v4tov4 listenport=7331 listenaddress=0.0.0.0 connectport=7331 connectaddress=$(wsl hostname -I)
  ```

## 4. Token & Session Expiration

### Symptoms
- Receiver webpage loads but displays `Session Expired` or `Invalid Token`.

### Fixes
- Session pairing tokens have an ephemeral TTL (default 15 minutes).
- If your phone was locked or the terminal session was restarted, scan the fresh QR code generated by the CLI.
- Ensure your device's system clock is set to automatic time synchronization.
